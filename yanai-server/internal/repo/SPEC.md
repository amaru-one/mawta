## Purpose
All hand-written SQL behind the HTTP handlers and job enqueueing: one file per domain area, each function taking a `pgx.Tx` already carrying tenant context.

## Contents
- `home.go` — `TenantToday`, `GetHome`. `me.go` — `GetMe`. `profile.go` — `GetProfile`.
- `classes.go` — `GetClassDashboard` (`Distribution` counts *asserted* niveles de logro from `competency_term_levels`, not computed grades; unexported helpers `getClassInfo`, `listSessions`).
- `sessions.go` — `GetSessionHeader` (incl. the section-average level), `GetSessionRoster` (attendance, voice notes — no observation, flag, level, trend or participation surface any more). `roster.go` — `RosterAsOf` (enrollment as of a date).
- `attendance.go` — `GetSessionMeta`, `UpsertAttendance`, `MarkAllPresent`, `MaybeStampAttendanceTaken`.
- `grades.go` — `GetStudentGrades`, `GetEffectiveScheme`, `GetComponentIDByCode`, `ListGradingComponents`, `CreateAssessment` (takes a `NewAssessment`; optional `StudentID` scopes the evidence to one student, optional `CriterionIDs` links it to criterios, `CountsTowardInternal` keeps it in or out of the school's own average), unexported `linkAssessmentCriteria`, `DeleteAssessment` (soft; returns a `DeletedAssessment` so the caller knows who to recompute), `CreateScore`, `CorrectScore` (supersedes the old score row; correcting twice concurrently 409s). `EvaluationEntry` carries no weight, reports `IsPersonal` and `CountsTowardInternal`, and lists the criterios it evidences with this student's level against each (one row of the evidencia × criterio grid); `ComputedGradeView` is the optional internal weighted system and carries no projection. The response carries no AI note summary — nothing had written a `note_summaries` row since the job kind was retired.
- `competencies.go` — `ListClassCompetencyLevels` (levels + conclusion state, with the mandatory-conclusion classification), `AssertCompetencyLevel` and `UpsertConclusion` (both append-only with supersession), `conclusionRequirement`.
- `criteria.go` — the criterios de evaluación layer: `ListClassCriteria` (every competencia of the class's área with its criterios, and — when scoped to a student — each criterio's `Evidence` row across the period plus the legacy `PeriodLevel`), `CreateCriterion` (rejects a blank description and a competencia outside the class's área), `DeleteCriterion` (soft), `AssertCriterionLevel` (append-only, **always anchored to an assessment**), `GetAssessmentCriterionGrid` (one evidence × its criterios × its roster, for the marking screen).
- `practice_scores.go` — create/delete/list unofficial practice scores.
- `voicenotes.go` — `CreateVoiceNote` (audio bytes in DB), `GetVoiceNoteFile`, `SetVoiceNoteStatus`.
- `notifications.go` — list (cursor on created_at), mark read/read-all.
- `terms.go` — `ResolveTerm` (explicit id or current term).
- `events.go` — `LogEvent`, `LogStudentReads` (mandatory for reads returning identifiable students).
- `jobs.go` — `EnqueueJob` (queue hardcoded 'default'; dedupes on `(kind, unique_key)` while available/retryable/scheduled/running).

## Inputs / Outputs
Inputs: `pgx.Tx` from `db.WithTenantTx` (or worker transactions) — RLS scopes every query. Outputs: response structs serialized by `httpapi`, plus rows in `jobs` and `events`.

## Conventions & Constraints
- Functions never open transactions; they run inside the caller's.
- Tenant id on inserts comes from `app.current_tenant_id()`, never a Go parameter (except `EnqueueJob`, whose tenant_id column is outside RLS).
- Scores and computed grades are append-only: corrections insert + stamp `superseded_at`; no in-place updates.
- Soft deletes (`deleted_at`) everywhere; filter them in every query.

## Conventions & Constraints addendum
- A competency with no level for a period is reported as null, never as C: "no desarrollada" and "en inicio" are different facts (RVM 048-2024, 5.1.2.2 p.1).
- **Nothing derives a nivel de logro.** `AssertCompetencyLevel` leaves `suggested_level_id` and `computed_grade_id` null on purpose: under RVM 094-2020 the level is the teacher's judgement of the period's evidence against the criterios, and a computed number sitting beside it in the UI is exactly the framing the norm moves away from. Criterio levels are evidence and are never rolled up.
- **A criterio level always names its evidencia.** `AssertCriterionLevel` requires an `assessmentID` and rejects a criterio the assessment does not declare (`criterion_not_in_evidence`) or a student the personal evidence does not belong to (`evidence_not_for_student`). 5.1.1.3 p.3 values *evidence* through the criterio; grading the criterio on its own inverts that into marking the ruler. The period-grain shape (`assessment_id` null) is legacy and read-only — `ListClassCriteria` still returns those rows as `PeriodLevel` because they are a student's academic history, but nothing writes them.
- **The school's own average is the only consumer of `counts_toward_internal`.** No criterio or competency query filters on it: the official judgement counts every piece of evidence regardless.
- `competency_term_levels.class_id` is provenance, not identity. Scope reads by the class's *área* and roster, so a level asserted from another class still counts for its own área and never counts for someone else's.

## Change Log
- 2026-08-29: Second purge pass. `profile.go` no longer queries `risk_flags` (dropped by `migrations/00003`, so `GetProfile` 500'd on any tenant with an active term) — `ProfileActivity` lost `AlumnosEnSeguimiento`. Deleted `observations.go` and `flagtypes.go` whole, and with them the entire per-session observation surface: `GetSessionRoster` no longer joins `session_observations` or `session_observation_flags`, and `RosterEntry` lost `ObservationNote` and `Flags` — the function is down to two round-trips (roster + voice notes) instead of three. `migrations/00007` drops the three underlying tables; see its own Change Log entry for why (neither the flag catalog nor the free-text note had a real writer or reader). Also deleted the `progress` computation from `GetClassDashboard` (`ComponentProgress`, the whole per-component registration query) — nothing rendered it, and it was already documented as unused before 2026-08-27. Unexported three functions with no caller outside `repo`: `GetClassInfo`→`getClassInfo`, `ListSessions`→`listSessions`, `LinkAssessmentCriteria`→`linkAssessmentCriteria`. Cascade: `internal/httpapi`, `internal/domain`, `migrations/00007`, `bruno`, `yanai-ui`.
- 2026-08-29: Deleted `siagie.go` whole — the end-of-period report screen it served is gone, and every row it returned is written and read on the student's grades screen. `MissingMandatoryConclusions`/`MissingConclusion` went with it: the report was their only caller, and the rule they encoded (a mandatory conclusión descriptiva blocks closing a period) is worth restoring *with* whatever screen next needs it rather than kept as SQL nothing runs. `GetSessionRoster` lost `LevelCode`, `PreviousLevelCode`, `Trend` and `ParticipationLevel`, and with them the three `computed_grades`/`grade_scale_levels` joins and the `termID` parameter — the lesson screen no longer shows a standing or a participation rating per row, and the roster query had been paying for a join per student to draw them. It also stopped selecting `transcription_status`, which no client read. `UpsertObservation` no longer writes `participation_level` (dropped in `migrations/00006`). Also deleted for want of a caller: `SearchClasses`, `UnreadNotificationCount`, `DismissNotification`, `SetVoiceNoteTranscript`, `LogJobEvent`, and `GetStudentGrades`' `note_summaries` read with `SummaryView`. Cascade: `internal/httpapi`, `internal/domain`, `migrations`, `bruno`, `yanai-ui`.
- 2026-08-28: Criterio levels moved from period grain to **evidencia × criterio**. `AssertCriterionLevel` takes an `assessmentID` instead of a `classID`+`termID` (the trigger denormalises both from the assessment) and supersedes on `(assessment_id, criterion_id, student_id)`, so `ecs_live_assessment_key` is now the key in use and `ecs_live_term_key` holds history only. It gained two guards: the criterio must be one the evidence declares, and personal evidence only accepts its own student. `ListClassCriteria` returns each criterio's `Evidence` row (ordered by the assessment's due date, because the row is read as a trajectory and what orders a trajectory is when the work happened) plus `PeriodLevel` for the legacy rows; the evidence cells are a second query rather than a join, since one criterio has many and folding them in would multiply every competencia row. Added `GetAssessmentCriterionGrid` for the class-wide marking screen — it reuses the canonical roster-as-of join (`section_memberships`, as in `RosterAsOf`/`GetSessionRoster`) as of the due date, narrows to one student for personal evidence, and deliberately returns **no mark**: the school's number is the other reading of the same evidence and belongs on the student's screen. `GetStudentGrades` now reports each assessment's `CountsTowardInternal` and each criterio ref's `Level`, so the evidence row can render its pickers without a second fetch. `GetMe` carries `UsesInternalGrading`. Cascade: `migrations/00005`, `internal/httpapi`, `internal/worker/handlers`, `bruno`, `yanai-ui`.
- 2026-08-28: Evidencia can now belong to one student. `CreateAssessment` takes a `NewAssessment` struct (the positional form had reached ten parameters) with optional `StudentID` — guarded against a student outside the class's roster — and optional `CriterionIDs`, written through the new `LinkAssessmentCriteria`, which applies the same "belongs to the class's área" check `CreateCriterion` does. Added `ListGradingComponents` (read from the class's effective scheme, so a component with nothing filed under it is still offered) and `DeleteAssessment` (soft; scores recorded against it stay, exactly as deleted criterios keep their levels). `GetStudentGrades` reports `IsPersonal` and filters both its queries by `student_id is null or student_id = $student`. In `classes.go` the four queries that fan assessments across the roster now build an explicit `expected` set of (assessment, student) pairs instead of multiplying by roster size — otherwise one student's personal evidence reads as missing for everyone. Cascade: `migrations/00004`, `internal/httpapi`, `yanai-ui`.
- 2026-08-27: Realigned the grade path with RVM 094-2020. Added `criteria.go`. `AssertCompetencyLevel` no longer reads `computed_grades` and stops writing `suggested_level_id`/`computed_grade_id`; `ListClassCompetencyLevels` no longer returns `suggested_level`. `GetStudentGrades` drops `weight` from each evaluation (they are evidence, not shares of a grade) and drops the projection columns from `ComputedGradeView`; it no longer inner-joins `grading_scheme_component_weights`, so an assessment shows as evidence whether or not its component is weighted, and it now attaches the criterios each assessment evidences via `assessment_criteria`. `GetClassDashboard` lost `Stats.EnRiesgo` and `AtRisk` (the risk tables are gone) and its `Distribution` now counts asserted levels rather than computed grades; it returns `(ClassDashboard, error)` instead of also returning at-risk student ids. Cascade: `yanai-ui/src/lib/api/dto.ts`, `internal/httpapi`.
- 2026-08-25: `GetStudentGrades` evaluations now carry `component_name` (`gc.name`) alongside `component_code`. The UI had been hardcoding a code→label map and title-casing unknown codes, which broke on multi-word competencia components; the class dashboard already used `gc.name`, so the two screens now agree. Cascade: `yanai-ui/src/lib/api/dto.ts`.
