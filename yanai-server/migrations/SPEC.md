## Purpose
The complete database schema as goose SQL migrations, applied in order against PostgreSQL 16 + pgvector.

## Contents
- `00001_initial_schema.sql` — the complete schema in one migration: every table, view, function, trigger and RLS policy, in final form. Squashed from an 18-file incremental history (`00001_bootstrap.sql` through `00018_competency_levels.sql`) on 2026-08-26 — see Change Log. Internally organised in the same order the original files were, as section-comment banners, so `git blame`/history intuition about "which era added this" still roughly holds even though the file boundaries are gone.
- `00002_evaluation_criteria.sql` — adds the CNEB layer below `competencies`: `capabilities` (capacidades), `performance_standards` (desempeños, per capacidad × grado), `evaluation_criteria` (criterios de evaluación — what a teacher writes/loads), `assessment_criteria` (join to assessments, sibling of `assessment_competencies`), and `evaluation_criterion_scores` (append-only per-student rubric results, on the tenant's existing AD/A/B/C scale). See Change Log.
- `00003_criterion_term_levels.sql` — makes evaluation por criterios workable under RVM 094-2020: `evaluation_criterion_scores.assessment_id` becomes nullable so a criterio level can be the teacher's judgement for a whole periodo rather than only a per-quiz cell; drops `computed_grades`' projection columns; drops the entire predictive subsystem (`risk_rules`, `risk_flags`, `risk_flag_evidence`, `notifications.risk_flag_id`). See Change Log.
- `00004_per_student_assessments.sql` — adds `assessments.student_id` (nullable): null means the assessment applies to the whole class, set means it is evidencia for that student alone. See Change Log.
- `00005_internal_system_optout.sql` — makes the school's own grading system optional (`tenants.uses_internal_grading`) and opt-out-able per piece of evidence (`assessments.counts_toward_internal`), and documents `ecs_live_term_key` as legacy read-only now that criterio levels are always anchored to an evidencia. See Change Log.
- `00006_drop_participation_level.sql` — drops `session_observations.participation_level` with the three-dot control it existed for, and rewrites two comment strings that named UI which no longer exists. See Change Log.
- `00007_drop_observations.sql` — drops the whole per-session observation subsystem (`session_observations`, `session_observation_flags`, `behavior_flag_types`), which had no payload column left once the note and the flag went the same way as participation. Redefines `privacy.anonymize_student()` first, since it wrote to `session_observations.note`. See Change Log.
- `ANALYSIS.md` — design notes: verified up/down/up cleanliness, expected-painful queries, ambiguities in the original product mock, argued constraints. Predates the squash and `00002`; still valid as design record, though its object counts (49 tables, 350 indexes, ...) are a snapshot from before `00016`/`00018`/`00002` and are superseded by the live counts against the current migration set. That mock (`yanai-views.html`) no longer exists in the repo — see root `SPEC.md`.

## Inputs / Outputs
Applied with goose (`GOOSE_MIGRATION_DIR` points here in production). Downstream consumers: every Go package, `seed/seed_demo_tenant.sql`.

## Conventions & Constraints
- Migrations are schema only — seed/demo data lives in `seed/`, never here.
- Append-only, never edit an applied migration; add a new numbered file (`00002_...` and up — `00001` is the squashed baseline, not a precedent for editing in place).
- Text + CHECK "enums" in SQL are mirrored as constants in `internal/domain/consts.go` (cascade when adding values).
- Every tenant table gets FORCE ROW LEVEL SECURITY; `jobs` deliberately has no RLS (nullable tenant_id, workers span tenants).
- Column/table `comment on` strings are load-bearing documentation — keep them current.
- **Never write ` -- ` inside a SQL string literal.** goose strips everything after a double dash when deciding whether a line terminates a statement, even inside quotes, so a `comment on ... is '... -- ...';` swallows every statement after it until some later line happens to end in a semicolon outside a comment. It fails as `unexpected unfinished SQL query: ... missing semicolon?`. `00004` has one and got away with it only because a following `create index` line closed the run-on. Punctuate comment strings with colons and commas.

- 2026-08-28: Added `00005_internal_system_optout.sql`. Two systems live in this app and must never feed each other: the official record (nivel de logro per competencia, RVM 094-2020) and the school's own weighted vigesimal mark (D.S. 009-2006-ED art. 37.4.f). Only `worker/handlers/recompute.go` reads it; the criterio path never does, which is the point. Deliberately no new index: `assessments_class_term_idx` stays non-partial because the evidence list and the dashboard counts share it and only the recompute cares about the flag. The criterio layer needed no DDL — `00003` had already made `evaluation_criterion_scores.assessment_id` nullable with `ecs_live_assessment_key` for the evidence-anchored shape, and this migration only re-documents the period-grain key as history now that Go stopped writing it. Verified up/down/up clean, and end-to-end against the seed tenant: a 20/20 on a `counts_toward_internal = false` assessment leaves the computed grade untouched while its criterio levels record normally. - 2026-08-28: Added `00004_per_student_assessments.sql`. `assessments` could only express a column for the entire class, so evidence belonging to one student — a recovery task, a re-done project, an oral defence replacing a missed group presentation — had nowhere to live except `practice_scores`, which is explicitly unofficial and never reaches the record. RVM 094-2020 does not require every student's evidence to be identical, so the schema should not either. `student_id` is nullable with a composite `(tenant_id, student_id)` FK to `students` and a partial index on `(class_id, term_id, student_id)` for the per-student read. - 2026-08-27: Added `00003_criterion_term_levels.sql`. RVM 094-2020 (mod. ## Open Questions
- `evaluation_criteria.performance_standard_id`'s capacidad is not checked against `evaluation_criteria.competency_id` — nothing stops linking a criterio to a desempeño that belongs to a different competencia. Every other cross-table consistency this strict in the schema is enforced by a trigger (e.g. `app.sync_score_denormalised`); this one is a known, deliberate gap pending a decision on whether it's worth one.

## Resolved
- *Should `note_summaries`/`note_summary_sources` and `competency_year_snapshots`/`year_final_situations` be dropped now that nothing writes to them?* No, on both counts, though for different reasons — moved here from Open Questions 2026-08-29 since neither was actually pending a decision. `note_summaries`/`note_summary_sources` lost their writer when the AI note-summary route was retired (2026-08-29); a real summary feature should fill them, not invent new ones. `competency_year_snapshots`/`year_final_situations` lost theirs when `internal/promotion` was removed (2026-08-27); they are the normative year-end acta records RVM 094-2020 5.1.3 requires, and whoever restores year-end close should write to them.
- *Is MINEDU's "B — En proceso" a pass?* (was: `passing_value` and `is_passing` disagreeing in the seed). The question was mis-posed. Under RVM 048-2024 "aprobado" is not a property of a level at all: an área counts as approved only "si cumple las condiciones establecidas en la tabla que dispone las condiciones de promoción o permanencia" (Anexo 09), and that table makes B sufficient in 1.°/3.°/4.° and insufficient in 2.°/5.°. The cutoff both columns encoded — nota 11 — comes from Anexo 07, which governed the 2020 school year only and expired when transitoria 8.3 extended the literal scale to all of Secundaria on 1 March 2021. `00018` therefore documented both columns as advisory, and `internal/promotion` (since removed, 2026-08-27) decided promotion by counting levels per área.
