## Purpose
Demo data, in one file, plus the runbook for hand-onboarding real data (school, section, students, teachers, classes, grading scheme).

## Contents
- `seed_demo_tenant.sql` — the complete worked example, in one file, as two independent `do $$ … end $$;` blocks applied in order:
  1. **Base tenant** — demo tenant, calendar, one teacher, both grade scales, the `matematica_estandar` scheme, the CNEB competencias for Matemática (4, `MAT-C1..C4`) plus the two transversales, each broken into its capacidades (`capabilities`); `MAT-C2` (the algebra strand Bimestre III actually covers) also gets its desempeños at grade 5 (`performance_standards`) and the teacher's own criterios de evaluación (`evaluation_criteria`, 3 of them). Section `5to B` with 10 students (`EST-2026-001`..`010`), class `MAT-5B`, sessions, 8 assessments (`Quiz 0`..`4`, 2 tareas, 1 examen). `Quiz 0` is already scored — `scores` on the vigesimal scale and `evaluation_criterion_scores` per criterio on the MINEDU AD/A/B/C scale — while Quizzes 1-4 stay published and unscored. On top of that, the teacher's judgement for the whole periodo: one period-grain `evaluation_criterion_scores` row per student per `MAT-C2` criterio (deliberately *not* a copy of the Quiz 0 levels), and the official `competency_term_levels` for `MAT-C2`. Diego has no rows in either — he submitted nothing, and an unevaluated competencia has no level rather than a C.
  2. **Arte 3ro A** — the full chain for a second subject — `ART` / Arte y Cultura, its two competencias now modelled as real `competencies` rows (`ART-C1`, `ART-C2`, not just `grading_components`), their 6 capacidades, one desempeño per capacidad at grade 3, and one criterio de evaluación per desempeño, each linked via `assessment_criteria` to the rubrica assessment that evidences it. Scheme `arte_competencias` (the two competencias at 50% each on the MINEDU AD/A/B/C scale, published), course `ART-3`, section `3ro A`, 10 students (`EST-2026-011`..`020`), class `ART-3A`, Mon/Thu 09:00, 8 scheduled sessions plus one ad-hoc session (Wed 2026-08-26 14:00, `schedule_id` null), and 6 published-but-unscored rúbricas.
- `README.md` — the onboarding runbook: how to apply the file locally and on the VPS, how to dry-run and undo, and the insert shapes for each entity.

## Inputs / Outputs
Requires migrations applied first. Produces the demo tenant whose tenant/actor UUIDs are baked into `bruno/yanai-api.yaml`, the deployed SPA build (GitHub secrets), and the server README — keep those stable across reseeds (cascade if they change).

## Conventions & Constraints
- Not a migration: applied by hand, after migrations. See `README.md` for the local and VPS commands.
- Not idempotent; each of the two blocks relies on a unique index to reject a second run (`tenants_modular_code_key`, `subjects_tenant_code_key`). Re-applying means resetting the database, not re-running the file.
- Each block sets `app.tenant_id` itself and lives in its own `do $$ … end $$;` block, independent of the other: FORCE RLS applies to the table owner, so unscoped writes are rejected or silently match nothing. Kept as two blocks rather than one merged declare section because several variable names (`v_class`, `v_course`, `v_section`, `v_scheme`, `v_version`, …) are reused for different entities and would collide if merged; the Arte block re-derives its own ids via `select … into` rather than reusing the base block's variables — guarded with `raise exception` when a lookup (tenant, academic year, term, grade level, teacher) comes up empty, so running it first fails loudly instead of silently matching nothing.
- The CNEB layer below `competencies` follows one pattern throughout: `capabilities` (capacidades, per competencia) → `performance_standards` (desempeños, per capacidad × grado) → `evaluation_criteria` (criterios de evaluación, the teacher's own precisado — optionally off a desempeño) → `assessment_criteria` (which assessment evidences which criterio). Not every capacidad needs a desempeño yet, and not every criterio needs a desempeño behind it — both are nullable on purpose, matching how a school actually loads its curriculum incrementally. See `README.md` §6 for the insert shapes.
- A `grading_scheme_versions` row needs `effective_from <= starts_on` of the earliest term it governs — `class_effective_grading_schemes` resolves by term start date, so a version dated "today" is invisible to the term under way, leaving a class with a scheme but no version.
- `subjects.icon_key` must be a sprite name from `yanai-ui/src/lib/icons.ts`; `toIconName()` silently falls back to `book`.
- The two grade scales are **not** interchangeable, whatever the old comment said. `minedu_ad_a_b_c` is ordinal with envelope 1-4 and **no `passing_value`**: AD/A/B/C carry no mark and "aprobado" is not a property of a level (see `migrations/SPEC.md` Resolved). `vigesimal_0_20` keeps its real cutoff and is for the school's own internal system or pre-2020 records — never the official record of a competencia.
- A competency's `kind` records whether it would count towards promotion (RVM 094-2020 5.1.3). Seed `transversal` rows with `subject_id = null`; anything else needs an área. Nothing in the app reads `kind` today — the code that decided the situación final was removed — but the distinction is normative and belongs in the data.
- Every class must have competencias, and every competencia its criterios: that is what the criterios screen checks and what the norm requires. A competencia seeded without criterios (Matemática's `MAT-C1`, `C3`, `C4`) shows up there as an explicit gap, which is the intended demo state, not an oversight.
- The base block enrolls **every** student existing so far into `5to B`. The Arte block must scope `section_memberships` to the students it just inserted, or it trips `section_memberships_one_at_a_time`.
- Dry-run with `begin; … set constraints all immediate; rollback;` — `check_weights_sum` is deferred, so a plain rollback never fires it.
- Undoing the Arte block needs `set_config('app.allow_hard_delete','on',true)` in the same transaction; delete a version's weights together with the version.
- In production the directory is bind-mounted read-only at `/seed` in the postgres container.
