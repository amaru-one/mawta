## Purpose
Monorepo root for Yanai, a mobile-first assistant for secondary school teachers in Peru: a Go API (`yanai-server/`), a SvelteKit SPA (`yanai-ui/`), and deployment infrastructure (`deploy/`, `.github/`).

## Contents
- `CLAUDE.md` — project instructions: the mandatory SPEC protocol every session must follow.
- `DEPLOY.md` — step-by-step runbook for deploying to a single DigitalOcean VPS (Postgres + API + Caddy via Docker Compose) with a GitHub Actions pipeline; `[HUMAN]` marks manual steps.
- `.gitignore` — root ignore rules.
- `yanai-server/` — Go API, migrations, seed data (see its SPEC.md).
- `yanai-ui/` — SvelteKit SPA (see its SPEC.md).
- `deploy/` — production Caddyfile and docker-compose (see its SPEC.md).
- `.github/workflows/` — CI and deploy pipelines (see its SPEC.md).
- `.claude/` — Claude Code local settings (tool config, no spec).

## Inputs / Outputs
Consumes nothing; produces the deployed app. `DEPLOY.md` assumes GitHub repo + GHCR + a VPS at `/srv/yanai`.

## Conventions & Constraints
- SPEC protocol in `CLAUDE.md` is mandatory: per-folder SPEC.md is source of truth, updated in the same turn as any change; stop if a change contradicts a spec.
- No real authentication yet — the deployed app must only ever hold the seeded demo tenant, never real student data.
- Generated/tool directories (`.svelte-kit/`, `node_modules/`, `.vscode/`, `.claude/`, `yanai-ui/build/`) and the empty `yanai-server/data/` carry no SPEC.md.

- 2026-09-04: **What gets evaluated is the competencia. A criterio is a tag on evidence, not something that is graded.** This corrects the model the app had been built on since 2026-08-27 and is the reason two screens exist and one was deleted. The rules, in full: the teacher assigns a **nivel de logro per competencia** and nothing else is ever recorded as a judgement; a piece of **evidencia** is an evaluation the teacher registers (a prueba calificada, an examen de recuperación, a tarea), tagged with the competencia and the criterios it speaks to; evidence **informs** that judgement and never averages, correlates or suggests it; and the **escala belongs to the evidence** — vigesimal 0–20, literal AD–C, or no value at all. This is a **UI-only first pass**. Added `yanai-ui/src/routes/class/[courseId]/students/` (the class list, which reports and navigates but never evaluates) and `students/[studentId]/` (where evaluating happens: the period's evidence with its values, then the competency level under it, with no accordion between them because the expansion state was deleted rather than restyled). `AddEvidenceDialog` became the `class/[courseId]/evidence/new/` route. Deleted from the UI: `class/[courseId]/evidence/[assessmentId]/` (the evidencia × criterio marking grid), `EvidenceCriteriaPickers`, `CriterionTimeline`, and the `assertCriterionLevel` / `getAssessmentCriteriaGrid` wrappers with their DTOs. **The server is untouched:** `POST /classes/{id}/students/{sid}/criterion-levels` and `GET /assessments/{id}/criteria-grid` still exist with no caller, `evaluation_criterion_scores` still holds the rows the seed writes, and the literal AD–C scale is rendered disabled because `assessments` has no `value_scale` column and `max_score` is `not null`. Phase 2 is the server half: a migration for the scale (`assessments.value_scale`, nullable `max_score`, `scores.scale_level_id`), `GET /classes/{classID}/students` to replace the class list's session-derived roster and its one-request-per-student level fetch, and deleting the criterio-level path end to end. Until then two SPECs describe the same tables from opposite ends — the UI ones are the product intent, the server ones the current code. See `yanai-ui/src/routes/SPEC.md`.
- 2026-09-03: **Home became an hour grid, and the demo tenant got a real teaching day.** The agenda's time rail is replaced by a proportional 07:00–17:00 grid — one hour is always 64px — with a Monday-to-Friday strip above it, and the "La semana" section is gone. Day navigation is bounded to that one week — the strip is the only control, there is no paging into the week before or after, and a day with no classes shows a line rather than an empty grid. What forced the rewrite was a real timetable: with a teacher working 08:00–16:00 the old rail computed its gaps in whole hours, so a 30-minute recreo was invisible *and so was the lunch hour* (12:15→13:15 is a difference of exactly 1, not more than 1), and its hour column labelled only the first class of each hour, leaving sessions that start at 11:30 or 13:15 with their time written nowhere on the screen. The grid answers both structurally: a gap is space, and every box carries its own start and end. UI-only — no API, DTO or migration change, since `getHome(date?)` already took a date and `today` ∪ `week` already covered the ISO week. Alongside it, `yanai-server/seed/seed_demo_tenant.sql` gained a third block: 5to B now takes **six áreas** (Matemática, Comunicación, Ciencia y Tecnología, Ciencias Sociales, Arte y Cultura, Tutoría) from the same teacher with the same ten students, on a five-block day with two recreos and lunch; `ART-3A` moved to Wed/Fri 16:15 so nothing overlaps. The demo tenant is 7 classes, up from 2. Its dates are fixed around 2026-09-03 and will go stale — see `yanai-server/seed/SPEC.md`. See also `yanai-ui/src/routes/SPEC.md`.
