## Purpose
Shared application logic: view-model types, Svelte stores, per-screen orchestration modules, and browser-capability helpers. Wire concerns live in `api/`; presentational pieces in `components/`.

## Contents
- `types.ts` — the app-side camelCase view models: `Course`, `Student`, `Session`, `Entry`, `Note`, `AppNotification`, `AppNotificationType`, `CompetencyLevel` and `CompetencyIndexItem`. Wire shapes live in `api/dto.ts`. `Entry`'s id is the natural key `${sessionId}:${studentId}`, since the server has no entry id, and it carries notes only. `Note.status` is `'draft' | 'saved'`, and `audioBlob` holds the blob right after recording while a server-loaded note fetches its audio on demand. `CompetencyIndexItem` is a component prop shape rather than a mapped view model, and lives here because a Svelte component cannot export a type from its instance script.
- `stores.ts` — the writable stores: `session` (`SessionState`, one of `'unknown'`, `'anonymous'` or `{ status: 'authenticated', role }`), `currentCourse`, `currentSession`, `students`, `entries`, `notes`, `notifications`, `teacher`, `canGoBack`, `usesInternalGrading`, plus the derived `unreadNotificationCount` and the `entryKey(sessionId, studentId)` helper that builds the key `entries` and `notes` are keyed by. `session` starts `'unknown'`, which is what holds the root layout's children back until the `GET /me` probe resolves. `usesInternalGrading` mirrors `GET /me`'s `tenant.uses_internal_grading` — whether the school runs its own weighted numeric system — and defaults to `true`, so a screen rendered before `/me` resolves shows its mark inputs. It gates mark inputs and the internal-grade card; a nivel de logro is unaffected by it. `canGoBack` is false until the SPA makes its first client-side navigation, and `TopBar`'s `useHistory` arrow reads it to choose between `history.back()` and its fallback href.
- `lesson.ts` — lesson-screen orchestration. `loadSession(sessionId)` reads `getSession`, fills `currentSession`, `currentCourse`, `students`, `entries` and `notes` through private `toEntry`/`applyRoster` helpers (dropping `discarded` notes and collapsing the three-state wire status to `draft`/`saved`), and fires `startSession` without awaiting when the header status is `scheduled`. `addNote(studentId, blob, durationSec)` prepends a local note, uploads it with `createVoiceNote`, then chains `saveVoiceNote` with one silent retry; a failed create removes the local note and raises a toast. It returns early unless `entries` already holds the student's key, so `loadSession` populates the roster stores even for a screen that renders no list. `removeNote(note)` drops the note first and re-inserts it if `discardVoiceNote` fails. `noteAudio(note)` returns the in-memory blob or fetches and memoises it. Attendance is not part of this module.
- `notifications.ts` — the feed over `GET /notifications`. `loadNotifications()` replaces the store; `markNotificationRead(id)` and `markAllNotificationsRead()` flip the store first and fire the request with errors swallowed, since the next poll reconciles. `aiGenerated` splits alerts from reminders.
- `grades.ts` — `Tier` (`'AD' | 'A' | 'B' | 'C'`), the MINEDU achievement-level vocabulary. Grade math is server-side; the client renders codes. `Tier` is also the app-side type for `types.ts`'s `CompetencyLevel.level`.
- `recorder.ts` — press-and-hold capture over `MediaRecorder`, plus Web Audio decode helpers. `MAX_RECORD_SEC` is 60, the same cap the server enforces, shared by the control that auto-stops and the screen that counts down. `startRecording()` returns an `ActiveRecording` with idempotent `stop`/`cancel`; the mic stream is cached after the first grant and its tracks are left live, so a later recording starts instantly. `audioContext()` lazily builds one shared `AudioContext` and resumes it when suspended. `decodeBlob` goes through Web Audio because media elements report unreliable durations for `MediaRecorder` webm blobs. `formatDuration(seconds)` renders `m:ss`.
- `toast.ts` — a single-slot `toast` store with an optional undo. `showToast(message, options?)` replaces the current toast and schedules its hide (2000ms with an `onUndo`, 1500ms without); `dismissToast()` clears it. Ids are monotonic so re-showing the same text re-triggers the transition.
- `haptics.ts` — `hapticTap`, `hapticRecordStart` and `hapticSuccess` over `navigator.vibrate`, guarded for environments without it.
- `icons.ts` — `ICON_NAMES`, the 24 symbol ids defined in `components/IconSprite.svelte`, and the `IconName` type derived from it. `<Icon name>` resolves to `#i-{name}` in that sprite.
- `api/` and `components/` — see their SPEC.md files. `assets/` holds `favicon.svg`, imported by `routes/+layout.svelte`.

## Inputs / Outputs
Consumes `api/endpoints/*`; feeds the route components through the stores and through direct return values.

## Conventions & Constraints
- Screens reach the lesson and notification mutations through these modules; the other screens call endpoints directly and hold their own `$state`.
- The optimistic-update idiom in `lesson.ts` and `notifications.ts` is a synchronous store write, a background API call, and a revert with an error toast on rejection — autosave with no submit button.
- `icons.ts` and `IconSprite.svelte` list the same 24 names (cascade).
- Store maps are replaced rather than mutated (`new Map(...)`) so subscribers see the change.
- Persistence is the server session cookie plus these in-memory stores; nothing in `src/` uses `localStorage` or `sessionStorage`. The one retry in the app is `lesson.ts`'s silent `saveVoiceNote` retry.

## Open Questions
- `toast.ts` hardcodes the undo label as `'Undo'`, the one English string in an otherwise Spanish UI.
- `types.ts` declares `AppNotificationType`'s `'tip'` member, which `toAppNotification` does not produce — it maps `kind` to `'risk'` or `'reminder'` only.
