## Purpose
Typed wrappers over the API routes, one module per area, all built on `../client.ts`. Each function takes and returns DTOs from `../dto.ts`; paths are written without the `/api/v1` prefix, which `client.ts` adds.

## Contents
- `auth.ts` — `login(username, password)` → `POST /auth/login`, resolving to `MeDto`; `logout()` → `POST /auth/logout`, bodyless. Paths under `/auth/` are exempt from `client.ts`'s unauthorized handler, so a 401 here reaches the caller.
- `home.ts` — `getMe()` → `GET /me`; `getHome(date?)` → `GET /home`, appending `?date=` when given. The server defaults the date to today in the tenant's timezone. `getMe` is also the session probe the root layout calls on mount.
- `profile.ts` — `getProfile(termId?)` → `GET /profile`, appending `?term_id=` when given.
- `classes.ts` — `getClassDashboard(classId, termId?)` → `GET /classes/{classId}/dashboard`; `getGradingComponents(classId, termId?)` → `GET /classes/{classId}/grading-components`, read from the class's effective scheme rather than from existing assessments; `createAssessment(classId, body)` → `POST /classes/{classId}/assessments`, resolving to `{ id }`; `deleteAssessment(assessmentId)` → `POST /assessments/{assessmentId}/delete`, a soft delete answering 204.
- `grades.ts` — `getStudentGrades(classId, studentId, termId?)` → `GET /classes/{classId}/students/{studentId}/grades`; `createScore(assessmentId, body)` → `POST /assessments/{assessmentId}/scores`; `correctScore(scoreId, body)` → `POST /scores/{scoreId}/correct`; `createPracticeScore(classId, studentId, body)` → `POST /classes/{classId}/students/{studentId}/practice-scores`; `deletePracticeScore(id)` → `POST /practice-scores/{id}/delete`. Scores are append-only server-side: a second correct against the same `score_id` answers 409 `already_superseded`.
- `competencies.ts` — `getStudentCompetencies(classId, studentId, termId?)` → `GET /classes/{classId}/students/{studentId}/competencies`; `assertCompetencyLevel(classId, studentId, body)` → `POST /classes/{classId}/students/{studentId}/competency-levels`, resolving to `{ id, level }`, with a re-assertion superseding the previous row; `upsertConclusion(classId, studentId, body)` → `POST /classes/{classId}/students/{studentId}/conclusions`, resolving to `{ id, status }`. A `final` conclusión without `includes_recommendations` answers 422 `missing_recommendations`.
- `criteria.ts` — `getClassCriteria(classId)` → `GET /classes/{classId}/criteria`, with no term parameter; `createCriterion(classId, competencyId, body)` → `POST /classes/{classId}/competencies/{competencyId}/criteria`; `deleteCriterion(criterionId)` → `POST /criteria/{criterionId}/delete`, a soft delete. The server rejects a blank description and a competencia outside the class's área. A competencia with no criterios comes back with an empty list.
- `students.ts` — `getClassStudents(classId, competencyId?, termId?)` → `GET /classes/{classId}/students`, the roster with each student's level in one competencia and its evidence count; `getStudentEvidence(classId, studentId, competencyId?, termId?)` → `GET /classes/{classId}/students/{studentId}/evidence`, that student's evidence for the period narrowed to the competencia server-side. Both build their query with `URLSearchParams` (`competency_id`, `term_id`) and append it only when non-empty. `competencyId` is optional: a class whose área has no competencias still has a roster.
- `sessions.ts` — `getSession(sessionId, q?)` → `GET /sessions/{sessionId}`, with `q` (`encodeURIComponent`-escaped) filtering the roster server-side; `startSession(sessionId)` → `POST /sessions/{sessionId}/start`, bodyless; `createVoiceNote(sessionId, studentId, audio, durationMs)` → `POST /sessions/{sessionId}/students/{studentId}/voice-notes` via `apiUpload`, as multipart `FormData` carrying `audio` (filename `note.webm`), `duration_ms` and `mime_type` (`audio.type` or `audio/webm`); `saveVoiceNote(voiceNoteId)` → `POST /voice-notes/{voiceNoteId}/save`; `discardVoiceNote(voiceNoteId)` → `POST /voice-notes/{voiceNoteId}/discard`. The server's two attendance routes (`PUT /sessions/{id}/attendance/{studentID}`, `POST /sessions/{id}/attendance/mark-all-present`) have no wrapper here.
- `notifications.ts` — `getNotifications(opts?)` → `GET /notifications`, with `URLSearchParams` carrying `kind`, `limit` and `before` (cursor pagination: `before` is the oldest `created_at` already held); `markNotificationRead(id)` → `POST /notifications/{id}/read`; `markAllNotificationsRead()` → `POST /notifications/read-all`, resolving to `{ marked_read }`. The unread badge is derived client-side in `lib/stores.ts` from the loaded feed.

## Inputs / Outputs
Thin: DTO in, DTO out, no mapping and no state. Routes mirror `yanai-server/internal/httpapi/router.go` (cascade). Nothing here catches — an `ApiError` from `client.ts` propagates to the caller.

## Conventions & Constraints
- View-model logic lives in `../mappers.ts` and orchestration in `lib/*.ts`; these modules only shape the request and hand back the response.
- There is no barrel file. Consumers import `$lib/api/endpoints/<resource>` directly.
- Deletes are modelled as `POST .../delete` and answer 204, which `client.ts` resolves as `undefined`.
- Query strings are built two ways: template interpolation in `classes.ts`, `competencies.ts`, `grades.ts`, `home.ts` and `profile.ts`, and `URLSearchParams` in `students.ts` and `notifications.ts`. `getSession`'s `q` is the one value passed through `encodeURIComponent`.
- The only level this layer writes is `assertCompetencyLevel`, and it always carries a level the teacher chose. `CriterionDto` and `CriterionRefDto` carry text only; there is no criterio-level route.
