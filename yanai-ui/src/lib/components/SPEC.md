## Purpose
Reusable presentational Svelte components shared across the app's screens. State and API calls stay in `lib/*.ts` modules or the owning route; these render props and emit events.

## Contents
- `TopBar.svelte` — screen header with back navigation. **A 64px band on `--surface-1`, closed by the `--hair` rule rather than by the step in value the old grey slab made**; every control is a 40px round target (they were 32px glyphs pulled together with a negative margin), the avatar carries the teacher's initials in `--aurora-deep`, and the bell's unread dot is ringed in the bar's own colour so it still reads against indigo type. The identity's name uses `--text-secondary`, not the ink: over `--surface-1` the saturated primary only reaches 4.4:1. `back` is the destination href; adding `useHistory` makes the arrow return to the previous screen instead, falling back to `back` when there is no in-app history (cold load, refresh, deep link). Modified clicks are never hijacked, so the fallback stays openable in a new tab. `recording` swaps the bell for a blinking accent dot + mono `REC`, so the lesson screen does not have to position anything over another component's box. A **home shortcut** sits before the bell on every screen whose `variant` is not `home` — no prop gates it, because "am I already on Home" is exactly what `variant` says. It is hidden while `recording` for the same reason the bell is: leaving the lesson screen mid-hold would lose the note. `Toast.svelte` — global toast (with undo) bound to `lib/toast.ts`.
- `Icon.svelte` / `IconSprite.svelte` — SVG sprite + `<Icon name>` resolver; names typed by `lib/icons.ts` (keep in sync).
- `RecordBubble.svelte` — the lesson screen's whole recording control: a 232px glass orb inside a 360×360 stage — four blurred `--aurora-*` lights turning under one `backdrop-filter` surface — that owns the press-and-hold state machine over `lib/recorder.ts`, plus the recording ripples and the crisp progress arc at `r=132` where one full turn is `MAX_RECORD_SEC`. Takes `armed` and `onrecorded`; binds `phase` and `elapsedSec` **out** so the owning screen renders the hint, the countdown and the topbar marker in their own pinned slots. Two CSS variables come the other way, from the owning screen: `--bubble-anchor` (where on the stage the orb's centre sits) and `--bubble-scale` (how much it shrinks on a short viewport) — the component owns the orb, the screen owns the composition.
- `VoiceNotePlayer.svelte` — playback of stored voice notes via `fetchAudioBlob`, with delete (via `ConfirmDialog`). No save control: saving is automatic, chained by `lib/lesson.ts`'s `addNote` right after the note is created.
- `LevelBadge.svelte` — MINEDU tier badge (AD/A/B/C via `lib/grades.ts`), used by `LevelPicker`, `CompetencyCard` and the class list. Since the palette change it is a **disc**, and the four tiers are one hue at four depths: AD `--fill-accent` (the tier the assistant highlights), A `--ink-deep`, B `--text-secondary`, C `--fill-tier-c` with a `--border-strong` outline. It reads through the `--fill-*` tokens, so the ladder came from the token swap rather than from a change here.
- `LevelPicker.svelte` — four `LevelBadge`s in a row, tappable, for recording a nivel de logro; takes a `size`. It offers no suggestion and never auto-selects. `CompetencyCard.svelte` — accordion card listing the competencia's criterios as **read-only text**, then the competency-level `LevelPicker`, then the conclusión descriptiva form (textarea, "incluye recomendaciones" checkbox, draft/final actions); used by the grades screen's competencias section.
- **The four controls of the evaluating screens** (`class/[courseId]/students/…`): `CompetencyIndex.svelte` — the typographic index that scopes a whole screen to one competencia (numerals for área competencias, a short mono code past a hairline for transversales; three states — faint/unset, muted/has a level, `--aurora-deep` with a 2px underline for the current one). What "has a level" means is the caller's business and differs per screen. `ScoreRuler.svelte` — a 0..`max` ruler with a 44px readout: 21 ticks, every fifth longer and labelled, the chosen one a 3px bar with a dot. Pointer-captured drag with the value read from the column under the finger, plus arrow keys; `onselect` fires **on release**, never mid-drag, so a drag is one write. `LevelScale.svelte` — the AD/A/B/C value of one piece of evidencia, four large letters with the chosen one underlined, for an assessment whose `value_scale` is `ordinal`. `LevelSelector.svelte` — the four-cell boxed selector carrying the MINEDU name of each level, for the competency level.
- `CompetencyIndex`, `ScoreRuler` and `LevelScale` are **line controls with no enclosure**; `LevelSelector` is the only boxed one. See the hierarchy rule below. `LevelScale` and `LevelSelector` deliberately show the same four letters in very different weights: the first values a piece of work, the second decides the official record.
- `AddPracticeScoreDialog.svelte` — dialog for adding unofficial practice scores (notas personales), which are not evidencia and never reach the record. `ConfirmDialog.svelte` — generic confirm modal.

## Inputs / Outputs
Props/events from route pages and `lib/` modules; no direct endpoint calls except audio fetch in `VoiceNotePlayer`.

## Conventions & Constraints
- Svelte 5 syntax; component-scoped styles using tokens from `src/app.css`.
- UI copy is Spanish.
- **A criterio is never graded — at all.** No component takes a level for a criterio, and none should be added. A criterio says what to look at in a piece of work; it is the ruler, not the thing marked (RVM 094-2020, 5.1.1.3 p.3). The only judgement any component records is the nivel de logro of a competencia (`LevelPicker`, `LevelSelector`).
- **Selection is painted in aurora; the record is painted in ink.** What the teacher is currently choosing or looking at — the competency index's current item, `ScoreRuler`'s thumb, `LevelScale`'s underlined letter, `LevelSelector`'s chosen cell — takes `--aurora-deep` or the action gradient. What has been *recorded* — a `LevelBadge`, a saved mark — takes the ink ladder. Without that split, a screen where everything is indigo cannot say which indigo means "you are here" and which means "this is filed".
- **Line controls inform; the boxed control decides.** On the evaluating screen the evidence values are drawn as lines (`ScoreRuler`) and the competency level as the one element inside a 1px stroke (`LevelSelector`). That difference is what stops "I valued this work" from reading as "I decided the official record" — do not box an evidence control, and do not unbox the level.
- **Nothing on the lesson screen carries achievement data.** A nivel de logro is a judgement over a period's evidence (RVM 094-2020, 5.1.1.3 p.2-3), and putting the current one — or a trend arrow off the previous one — beside a name being recorded against invites the second to colour the first. Levels are read and written on the student's grades screen, which is where the evidence is. (This rule outlived the roster row it was written for.)
- **`RecordBubble` is the one deliberately stateful component**, as `MicButton` was before it, and it is stateful for a concrete reason: `setPointerCapture` has to be called on the element that received the `pointerdown`, so the press-and-hold machine cannot be hoisted into the owning page without forwarding four pointer events through props.
- **The bubble's colour lives *under* the glass, never on it.** `RecordBubble` paints four blurred, screen-blended lights in a clipped circle and lays one translucent `backdrop-filter: blur() saturate()` surface over them: the teacher sees the blur of the colour and of the page behind it, which is what makes the orb read as glass. Two consequences to keep: the ambient glow behind the orb is not decoration — over flat white the surface would have nothing to refract and would read as a solid disc — and the blur radius is proportional to the orb (15px at 232px), because blurring further washes the four hues into one pale disc.
- **The orb moves in every state, including the drained one.** Waiting for a student drains the colour (`saturate(.4)`) but never stops it turning — a still orb reads as a broken one. The four lights ride one shared `corriente` keyframe (22s/turn, linear, a quarter-loop apart via `animation-delay`) that reads as one body rotating on its vertical axis: each light enters compressed at one edge, widens to full strength crossing the front, and exits compressed at the other. **Speed changes are `Animation.updatePlaybackRate`, never `animation-duration`** — swapping the duration restarts the animation's phase, which would jump the orb the instant a hold commits. `setSpin()` (called from an `$effect` on `phase`) sets rate 8 (≈2.75s/turn) the moment `phase === 'recording'`, and 1 (22s/turn) otherwise — idle and armed turn at the same slow tempo; only an actual recording is fast. `prefers-reduced-motion` still wins: the media query below removes `.blob`'s animation outright, so there is nothing for `setSpin` to accelerate.
- **SVG filter and gradient ids are namespaced with `$props.id()`.** `url(#…)` resolves document-globally, so a static id silently breaks the moment a second instance mounts.
- **Anything animated respects `prefers-reduced-motion`, SMIL included.** SMIL cannot be switched off by a media query, so reduced motion is handled by not rendering the `<animate>` children at all. Information-bearing motion — the recording progress arc — stays.
- **Nothing derives a level from anything.** No component computes, suggests or pre-selects a competency level — not from marks, not from other levels, not from how many criterios an evidence declares.
- **`ConfirmDialog` ports its root node to `document.body` on mount** (`$effect` + `bind:this`, removed on unmount) rather than rendering it where the `{#if}` sits. `position: fixed` alone does not guarantee a true page-level overlay: without a transformed/filtered ancestor it still positions against the viewport, but *stacking* is a separate mechanism — a fixed descendant's `z-index` is only compared inside the nearest ancestor that already opened its own stacking context (any `position` + `z-index` pair). Any screen that renders this dialog under such an ancestor would silently cap its `z-index: 2000` there. Porting the node sidesteps this for every caller, present or future, rather than requiring each screen to keep its z-index scale clear of 2000.
