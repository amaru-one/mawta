## Purpose
Reusable presentational Svelte components shared across the app's screens. State and API calls stay in `lib/*.ts` modules or the owning route; these render props and emit events.

## Contents
- `TopBar.svelte` — screen header with back navigation. `back` is the destination href; adding `useHistory` makes the arrow return to the previous screen instead, falling back to `back` when there is no in-app history (cold load, refresh, deep link). Modified clicks are never hijacked, so the fallback stays openable in a new tab. `Toast.svelte` — global toast (with undo) bound to `lib/toast.ts`.
- `Icon.svelte` / `IconSprite.svelte` — SVG sprite + `<Icon name>` resolver; names typed by `lib/icons.ts` (keep in sync).
- `CourseCard.svelte` — home-screen class card.
- `RosterRow.svelte` — one student row on the lesson screen: name (linking to that student's grades), attendance, mic and any voice notes. Nothing else — see Conventions. `AttendanceControl.svelte` — present/absent toggle.
- `MicButton.svelte` — press-and-hold recording button over `lib/recorder.ts`. `VoiceNotePlayer.svelte` — playback of stored voice notes via `fetchAudioBlob`.
- `LevelBadge.svelte` — MINEDU tier badge (AD/A/B/C via `lib/grades.ts`), used by `LevelPicker`, `CriterionTimeline`, `CompetencyCard` and the lesson screen's section average.
- `LevelPicker.svelte` — four `LevelBadge`s in a row, tappable, for recording a nivel de logro; takes a `size` so it can render small inside an evidence row and full-size for a competencia. It offers no suggestion and never auto-selects. `CriterionTimeline.svelte` — **read-only**: one criterio's text plus its row across the period's evidence (a badge + date + title per cell, scrolling inside itself), and the legacy period-grain level labelled as an earlier record where one exists. `EvidenceCriteriaPickers.svelte` — the criterios one piece of evidencia declares, each with its own `LevelPicker`; this is the only place a criterio level is recorded, and it always knows which evidencia it belongs to. `CompetencyCard.svelte` — accordion card wrapping the competencia's criterios (each a `CriterionTimeline`), then the competency-level `LevelPicker`, then the conclusión descriptiva form (textarea, "incluye recomendaciones" checkbox, draft/final actions); used by the grades screen's competencias section.
- `AddEvidenceDialog.svelte` — dialog for filing one piece of _evidencia_ (título, tipo, componente, sobre, entrega, "cuenta para el promedio interno", and checkboxes for the criterios it evidences). `usesInternalGrading` false hides both the "sobre" field and the internal-average checkbox — a school with no numeric system has no average for evidence to count towards. Takes `scope`: `'student'` (the grades screen — the caller adds the `student_id`) or `'class'` (the class dashboard). The scope is a fixed prop shown as a caption, never a control — which screen you are on is already the answer.
- `AddPracticeScoreDialog.svelte` — dialog for adding unofficial practice scores (notas personales), which are not evidencia and never reach the record. `ConfirmDialog.svelte` — generic confirm modal.

## Inputs / Outputs
Props/events from route pages and `lib/` modules; no direct endpoint calls except audio fetch in `VoiceNotePlayer`.

## Conventions & Constraints
- Svelte 5 syntax; component-scoped styles using tokens from `src/app.css`.
- UI copy is Spanish.
- **A criterio is never graded on its own.** `CriterionTimeline` deliberately has no `LevelPicker`; levels are recorded in `EvidenceCriteriaPickers`, inside the evidencia they were read from (RVM 094-2020, 5.1.1.3 p.3 values evidence _through_ the criterio). Putting a picker back on the criterio row would restore exactly the inversion this design removed.
- **The roster row carries no achievement data.** It is the pass-the-register row: attendance, a voice note. A nivel de logro is a judgement over a period's evidence (RVM 094-2020, 5.1.1.3 p.2-3), and putting the current one — or a trend arrow off the previous one — beside a name being marked present invites the second to colour the first. Levels are read and written on the student's grades screen, which is where the evidence is.
- **Nothing derives a level from another level.** The timeline displays cells; it never aggregates them, and no component computes a competency level from criterio levels or from marks.

## Change Log
- 2026-08-29: Deleted `FlagButton.svelte` — its only consumer, `RosterRow`, dropped the flag along with the whole per-session observation subsystem it wrote to (`session_observations`, `session_observation_flags`, `behavior_flag_types`; see `yanai-server/migrations/SPEC.md`). That subsystem's flag catalog had no seed or provisioning path in any environment, so the button could never actually raise a flag. `RosterRow` now renders only `AttendanceControl` and `MicButton`. Cascade: `lib/lesson.ts`, `lib/types.ts`, `yanai-server`.
- 2026-08-29: `RosterRow` lost three things: the `ParticipationControl` (deleted — this was its only consumer), the per-row `LevelBadge`, and the "A →" previous-tier arrow. What is left is what passing the register actually needs, and the name/badge row collapsed to a single control. `AiSummaryCard` and `ProgressRing` were deleted outright: the first had nothing to render once the summary route went (nothing had written a `note_summaries` row since the job kind was retired), and the second had had no importer since 2026-08-27. `ConfirmDialog` lost its `cancelLabel` prop — every one of its four call sites took the default. Cascade: `lib/lesson.ts`, `lib/types.ts`, `src/app.css`, `routes/class/[courseId]/lesson/[sessionId]/`, `routes/grades/[studentId]/`.
- 2026-08-28: Criterio levels moved into the evidencia. Deleted `CriterionRow.svelte` (criterio text + its own picker) and replaced it with `CriterionTimeline.svelte`, which is read-only and shows the criterio's row across the period's evidence — read left to right, C → B → A → A is a student who learned to justify, which no single value could say. Added `EvidenceCriteriaPickers.svelte`, the new and only capture point, with per-criterio saving state so one slow save does not freeze the row beside it. `CompetencyCard` swapped `onCriterionLevelChange` for `onopenevidence` (a cell opens the work it came from) and its caption now says the level is read from the criterios in time rather than calculated from them. `AddEvidenceDialog` gained `usesInternalGrading` and the "cuenta para el promedio interno" checkbox, defaulting off for per-student evidence — a recovery task that lifted one student's average hands them an opportunity nobody else had. Cascade: `lib/api/`, `routes/grades/[studentId]/`, `routes/class/[courseId]/evidence/[assessmentId]/`.
- 2026-08-28: Added `AddEvidenceDialog.svelte`. Until now nothing in the app called `createAssessment`, so evidence could not be added at all and the button that looked like it did ("Añadir evaluación") actually created a nota personal. The kind picker offers all nine `AssessmentKind`s; the component picker comes from the class's scheme, since the accordion groups by component and the kind rides as a label on the row.
- 2026-08-27: `LevelPicker` lost its `suggestedLevel` prop and the "Sugerido: X" caption, and gained `size`. `CompetencyCard` gained the criterios block above the level picker, with a caption stating that the level is the teacher's judgement and is not calculated from the criterios or the marks. Added `CriterionRow.svelte`. The criterios sit _above_ the level deliberately: they are what the judgement is made against, so the reading order matches the reasoning order.
- 2026-08-26: Added `LevelPicker.svelte` and `CompetencyCard.svelte`. Both follow the app's established overflow idiom for long CNEB competency names next to fixed-width badges: `.grow{flex:1;min-width:0}` on the text (no ellipsis, free wrap), `flex-shrink:0` on badges/icons, `align-items:flex-start` on rows whose text can wrap to 2+ lines — same pattern already used by `RosterRow`'s name/badge row and the grades screen's evaluation rows.
- 2026-08-25: `TopBar` gained `useHistory`, for screens reachable from more than one place where any fixed back destination is wrong for every caller but one.
- 2026-08-24: Initial spec created retroactively, describing current contents.
