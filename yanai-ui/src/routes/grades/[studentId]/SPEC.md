## Purpose
Student grades screen: one student across the whole área, organised by grading component — the inventory of everything filed for them. It leads with the official MINEDU record (the nivel de logro per competencia), then the evidencia with its values, then the school's optional internal weighted grade, collapsed.

Its sibling is `class/[courseId]/students/[studentId]`, which takes one competencia at a time and puts the evidence directly above the decision. That one is for evaluating; this one is for reading a student whole.

## Contents
- `+page.svelte` — loads `getStudentGrades` + `getStudentCompetencies` + `getClassCriteria` + `getGradingComponents` (`Promise.all`), owns local `$state` for all four (this screen predates and does not follow the `mappers.ts`-only convention for `StudentGradesDto`; the competencias code does, via `toCompetencyLevel`; criterios and components are consumed as DTOs). Renders, in order: "NIVELES DE LOGRO POR COMPETENCIA" (a `CompetencyCard` per competency, each holding that competencia's criterios), "EVIDENCIA" (the evaluation-module accordions plus "Añadir evidencia"), the collapsed "Sistema interno de la IE" card, and "NOTAS PERSONALES" with "Añadir nota personal".

## Inputs / Outputs
Route param `studentId`; `classId`/`studentName`/`courseName` travel as query params (`?class=&name=&course=`) since no endpoint returns them and there is no other student lookup. Mutations: `createScore`/`correctScore` (with retry-on-`already_superseded`), `deleteAssessment` from `lib/api/endpoints/classes.ts`, `createPracticeScore`/`deletePracticeScore`, and `assertCompetencyLevel`/`upsertConclusion`. "Añadir evidencia" is now a **link** into `class/[courseId]/evidence/new?student=&name=&course=`, so this screen no longer calls `createAssessment` itself. Reads `usesInternalGrading` from `lib/stores.ts`, loaded once by the root layout from `GET /me`.

## Conventions & Constraints
- **Order is the argument.** Competencias first, marks second, weighted grade last and collapsed. RVM 094-2020 determines achievement from the teacher's judgement against the criterios; a layout that led with a computed number would contradict the norm no matter what the copy said.
- **Nothing on this screen derives a level.** No mark and no count is ever summed, averaged or rolled up into the competency level; the competency card says so in plain Spanish under its picker. There is no suggested level anywhere.
- **Criterios are never graded, here or anywhere.** An evidence row lists the criterios it declares as read-only text, and the competency card lists that competencia's criterios the same way. A criterio says what to look at in the work; it is the ruler, not the thing marked (RVM 094-2020, 5.1.1.3 p.3). The one judgement recorded is the nivel de logro of the competencia.
- **This screen reads a student across the whole área; the evaluating screen is `class/[courseId]/students/[studentId]`.** Both can assert a competency level. This one is organised by grading component (an inventory of everything filed), that one by competencia with the evidence directly above the decision.
- **The school's internal system is optional.** With `usesInternalGrading` false the mark inputs and the "Sistema interno de la IE" card disappear entirely — the official record never came from a number in the first place. The same holds per piece of evidence: a mark input appears only for `value_scale: 'numeric'`. Evidence filed out of the average shows a "Fuera del promedio interno" tag rather than being hidden; it is still evidencia.
- **Evidence added here is for this student alone.** "Añadir evidencia" links to `evidence/new` with `?student=`, so the form files it against that student; class-wide evidence is filed from the área, which speaks for the class rather than for one student. The form says so in its caption and the row carries a "Solo este alumno" badge, because an assessment that quietly appeared on thirty other screens would be indistinguishable from one that did not.
- The accordion groups by **grading component**, not by kind. The kind (Quiz, Tarea, Proyecto…) rides as a label on the row instead: the component is what the school's scheme is built from, whereas the kind is descriptive. A row's kind and its section can therefore legitimately disagree.
- Deleting evidence is soft and the confirm dialog says what survives: the notes stay in the student's history but stop being shown and stop counting in the internal weighted grade. There is no edit — same rule as criterios, for the same reason.
- "Añadir nota personal" is a _different_ thing from "Añadir evidencia" and must stay visibly so. A nota personal never reaches the record; evidencia does. Until 2026-08-28 the only button on this screen said "Añadir evaluación" and created a nota personal, which is exactly the confusion the two labels now prevent.
- Marks carry **no weight**. `EvaluationDto` has no `weight` field and the module headers show only "N/M evaluadas". The standing caption under "EVIDENCIA" states that marks do not determine the nivel de logro — that sentence is load-bearing, not decoration.
- The "Sistema interno de la IE" card is the weighted `computed_grade`, collapsed by default and labelled as the school's own system rather than the MINEDU record (D.S. 009-2006-ED art. 37.4.f). It carries no projection: the norm has no forecast grade, and the columns were dropped in `00003`.
- A competency with `level === null` means "not evaluated this period" (RVM 048-2024, 5.1.2.2 p.1) — rendered blank/dash, never as C. An `ordinal` piece of evidence with no letter yet reads "Sin valorar" for the same reason.
- Asserting a competency level is autosave-instant: tap = saved, matching the rest of the app. Each save is a deliberate per-tap write, not a background sync — see `CompetencyCard`'s doc comment.
- Long CNEB competency and criterio texts are full sentences: every row follows the app's overflow idiom — `.grow{flex:1;min-width:0}` on the text, no ellipsis, `flex-shrink:0` on badges/icons, `align-items:flex-start` on rows whose text can wrap.
- A `final` conclusión descriptiva without the "incluye recomendaciones" checkbox is blocked client-side in `CompetencyCard`, mirroring the server's 422 `missing_recommendations` — the server is still the source of truth.
