## Purpose
One student, one competencia: the evidence of the period with its values, and under it the nivel de logro of the competencia. This is the screen where a teacher evaluates.

## Contents
- `+page.svelte` — `TopBar back="/class/{courseId}/students" useHistory`, the student's name at 34px over the shared rule, a mono sub-line carrying the class name, the `CompetencyIndex` over this student's competencias, the competencia's name at 15px/600, then two sections:
  - **Evidencias del periodo**, under the hint "Cada evidencia se valora en su propia escala. Se guarda al tocar." One hairline-ruled card per piece: the title, a mono `KIND` or `KIND · DD MMM` line built from `due_at`, the criterios it is tagged with as read-only text (or "Sin criterios declarados."), the control its scale calls for, a "No entregó" row with a marker square and `aria-pressed`, and a `Fuera del promedio interno` tag when `counts_toward_internal` is false. The empty state reads "Esta competencia no tiene evidencia este periodo. Se registra desde el área, en «Añadir evidencia», enlazándola a sus criterios."
  - **Nivel de logro en esta competencia**, under the hint "Lo pones tú, leyendo lo de arriba. Ninguna nota lo calcula." A `LevelSelector`, then the conclusión descriptiva block: a requirement line, a textarea, an "Incluye recomendaciones personalizadas" checkbox, and `Guardar borrador` / `Marcar como final`.

## Inputs / Outputs
Route params `courseId` and `studentId`. `?name=`, `?course=` and `?comp=` carry the student name, the class name and the selected competencia, since no endpoint returns them — the same convention `grades/[studentId]` uses for the first two. Reads `getStudentCompetencies` and `getClassCriteria` in one `Promise.all`, then `getStudentEvidence` for the selected competencia, refetched by an `$effect` on every change so the server does the narrowing. Mutations: `createScore` / `correctScore`, `assertCompetencyLevel`, `upsertConclusion`. Reads `usesInternalGrading` from `lib/stores.ts`.

## Conventions & Constraints
- The selected competencia survives a remount through `?comp=`: `selected` is local `$state` and SvelteKit remounts the route on every navigation, so the URL is what distinguishes "never chosen" from "chosen, then torn down". `selectCompetency()` writes it with `goto('?' + params, { replaceState: true, keepFocus: true, noScroll: true })`, and `students/` propagates its own selection into the link to each row.
- On this screen the index's `hasLevel` means this student already has a non-null level in that competencia.
- The order of the screen is evidence first, decision second, with a heading and extra space between them.
- Every evidence card is open with its control in place; there is no accordion and no per-card expanded state.
- The rulers are lines with no enclosure, and `LevelSelector` is the one element on the screen inside a 1px stroke.
- Nothing computes the level: there is no suggestion, no average and no roll-up, and the copy under the selector says so. A criterio renders as text only.
- Evidence is attributed to a competencia through its criterio tags, server-side: a piece belongs here when it is tagged with at least one criterio of the selected competencia. A piece tagged with none appears on `grades/[studentId]` instead.
- The control is chosen by the evidence. `value_scale: 'numeric'` with a non-null `max_score` and `usesInternalGrading` on draws a `ScoreRuler` over `max_score`; `ordinal` draws a `LevelScale`; otherwise the card draws a line of copy in place of a control — "El colegio no lleva sistema propio de notas…" for a numeric piece with internal grading off, and "Sin valor: esta evidencia se registra y se lee, no se puntúa." as the fallback.
- `LevelScale` and `LevelSelector` show the same four letters in different weights: the first values a piece of work, the second records the nivel de logro of the competencia.
- "No entregó" writes `status: 'not_submitted'` with a null value; untoggling writes `graded` back with the mark held in `lastValue`, a `Map<assessmentId, { rawValue, level }>` populated the instant before marking, since the server nulls the value when the piece is marked not submitted. `lastValue` is session-only and holds nothing for a piece that was not graded before. The ruler and the letters stay enabled under the mark, so picking a value there calls `writeScore(..., 'graded', v, ...)` directly. The toggle is a row with a marker square.
- Saves are per tap and patch `evidence` in place rather than refetching — `applyScore` replaces the row's `attempts` with the single new attempt — and `savingScore` is a `Set` keyed by `assessment_id`, so one slow write leaves the card beside it responsive. A level write patches `levels` with the new level and a fresh `asserted_at`.
- The conclusión descriptiva is always open rather than behind a disclosure. Its requirement line comes from `conclusion_requirement`, and a `final` conclusión without the recommendations checkbox is blocked client-side with the toast "Una conclusión final debe incluir recomendaciones", mirroring the server's 422. Both buttons stay disabled while saving or while the draft is blank. An `$effect` on the current competencia re-seeds the draft from `conclusion_body`.
- Haptics are the "No entregó" toggle; `CompetencyIndex`, `ScoreRuler`, `LevelScale` and `LevelSelector` tap internally. The screen has no dialogs. The error state is "No se pudo cargar al alumno." over a `Reintentar` button; a failed evidence refetch toasts "No se pudieron cargar las evidencias de esa competencia".

## Open Questions
- `CompetencyLevelDto` does not carry `includes_recommendations`, so the checkbox starts unticked even when a conclusión already exists, and re-saving an existing final one means re-ticking it. Carrying the state across a reload means adding the field to the DTO.
- The sub-line names the class but not the periodo: no read on this screen returns a term label, only `term_id`.
