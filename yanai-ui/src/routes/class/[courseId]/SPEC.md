## Purpose
**The área** ("Foco" layout): one class seen whole. A name headline + mono sub-line, a hero for
today's session, a quiet hairline-ruled nav list into the criterios de evaluación and the
class-wide "Añadir evidencia" action, and two horizontal rails of upcoming and past sessions.
Every session on this screen — the hero included — is a link into that session's recording
screen. The área is a reference surface and a launcher; it is not where the teacher works.

## Contents
- `+page.svelte` — loads `getClassDashboard` alone. Renders: `.clsname` headline + `.clscount` mono sub-line; a `.hero` `<a>` for `next_session` (only when non-null) into `lesson/{session_id}?from=area`, carrying a clock-derived phase label, the start time at 40px and a `.hero-row` of the topic line beside a trailing `chevron-right`; a `.quiet` nav of **three link rows** — `students/` ("Alumnos", trailing `chevron-right`), `criteria/` (trailing `chevron-right`) and `evidence/new/` ("Añadir evidencia", trailing `plus`); and two `.hscroll` rails of `.lcard`s for `upcoming` and `past`, each a date block beside the topic, both showing the time range and the past ones a trailing 14px `mic` — every card's `href` is `lesson/{session_id}?from=area` too.

## Inputs / Outputs
Route param `courseId` (class UUID); consumes `getClassDashboard` from `lib/api/endpoints/classes.ts`. **No mutations** — the screen is a launcher, and filing evidence moved to `evidence/new/`.

## Conventions & Constraints
- Term selection defaults to the current term server-side (`term_id` query optional).
- **The screen follows the app-wide vocabulary now, not the "Foco" mockup.** That mockup governed it until 2026-09-08, when the whole app moved onto the recording screen's palette and type; the approved canvas «Yanai en estilo burbuja» is the source of truth for this screen. It still overrides `.body` padding locally (`18px 20px 30px`) — the rails cancel the gutter with a negative margin, so the number has to be known here — and it still sets its own `.eyebrow` **margin**, but the eyebrow's type is now the app's.
- **Today's session is the screen's one loud element; nothing else competes.** This reverses the rule that stood here from 2026-09-02 to 2026-09-08 ("no dark element and no primary action"): the hero now carries the action gradient, because with every rail card tinted the hero had become just another tinted block, and today's session is the only one of them a teacher opens without thinking. What has *not* come back is a second action: there is still **no "Grabar nota de voz" button**, because tapping a session already binds the note to that session, and the rails stay reference. One loud thing, and it is the session you are in.
- **Every link off this screen into a session carries `?from=area`** — the hero and both rails alike. It marks that this particular bubble has área one step behind it in browser history, which is what lets that bubble drop its own "Ir a {área}" button and rely on the back arrow instead: see `lesson/[sessionId]/SPEC.md`'s navigation rule for why (área↔burbuja links that always push forward were growing the history stack without bound). A bubble reached from Home carries no such param and keeps its button, since Home never links to área at all.
- **The área has two entry points, and only one of them is a session.** From a bubble, via its "Ir a {área}" button (the path Home feeds). And from **`profile/`'s "MIS CLASES" list**, which links straight here — the app's only date-independent way in, and the only one that works when Home is empty because the class's sessions fall outside the current ISO week (a past term, or one not yet started). `TopBar`'s `useHistory` already covers both callers, so back returns to whichever screen the teacher actually came from; nothing here needs to know which. The `?from=area` rule above is unaffected either way: what it marks is whether *área* sits one step back from the bubble, not how the teacher reached área.
- **The hero is a link, not a heading.** Today's session appears in neither rail — `past` and `upcoming` exclude it — so the hero block is the only way to reach it, and the whole block is the `<a>`. It carries `chevron-right` in a `.hero-row` beside the topic, borrowing the `.quiet-row` idiom so "chevron means it navigates" holds everywhere on the screen.
- **Past cards carry a `mic`; upcoming cards do not.** The glyph says this card leads somewhere you can record, which is not yet true of a session that has not happened. The "Clases anteriores" eyebrow also takes a `.railhint` line ("Toca una clase para dejarle una nota de voz") — the one piece of instructional copy on the screen, and it earns its place because the binding between a note and a session is invisible otherwise. "Próximas clases" gets neither.
- **A card's width follows its topic** (`width: max-content` between `min-width: 190px` and `max-width: 300px`, then a 2-line clamp). Session topics are teacher-written and run long — "Resolución de problemas de cantidad con fracciones heterogéneas" is a realistic one — and a fixed 210px card cut them at about 50 characters with no way to read the rest. The rail is deliberately ragged as a result; that is the accepted cost.
- **The rails bleed past the body gutter** (`margin: 0 -18px 30px` against `padding: 0 18px 8px`) so a card can sit half-cut at the phone edge. That cut is the only thing telling you the row scrolls, so the gutter number is duplicated here rather than inherited.
- **Nothing aggregate is rendered.** `ClassDashboardDto` still carries `distribution`, `stats`, `grades_pending`, `attendance_unmarked`, and `SessionSummaryDto` still carries `present_count` / `roster_count` / `missing_grades` / `has_comments`, but the screen renders none of them — it is a launcher, not a report. The session counters joined that list on 2026-09-02 when the past cards' chips were removed; `present_count` in particular was reporting a number nothing has written since attendance capture left the app. (This corrects a stale claim: the spec previously described a rendered "Distribución de logros" bar, which had already been cut from the file.)
- **The hero phase label is clock-derived, not `status`-derived.** The server only ever puts a session in `next_session` that is dated today, is `scheduled`/`in_progress`, and has not yet ended (`scheduled_end_at >= now()`) — a finished session drops into `past` ("Clases anteriores") instead, and with two sessions in a day the hero is the current or next one. The "Hoy · …" label is then computed client-side from `scheduled_start_at`/`scheduled_end_at` (full RFC3339 instants) against a `now` refreshed every 60 s while the page is open: `now < start` → Sin iniciar, `start ≤ now ≤ end` → En curso, `now > end` → Finalizada. "Finalizada" is now only a ≤60 s boundary between the server's pick and the client clock crossing the end, or a page left open past the end; the steady state for an ended session is that the hero is gone. `cancelled`/`rescheduled` sessions never reach the hero, so the phases are total. The phase is computed in-template (`{@const}` under the `{#if}`) so it re-reads `now` on each tick, and the labels are written in sentence case because `.hero-lbl` uppercases them in CSS.
- **This is where class-wide work is set up, and only class-wide work.** The área speaks for the class, so filing a column every student will be graded on starts here; anything scoped to one student starts on that student's screen. `evidence/new/` states its scope in a caption rather than offering a picker.
- **"Alumnos" leads the nav** — it is the row a teacher reaches for between classes, while the other two are set-up work. All three rows are `<a>`s now; `.quiet-row` keeps its explicit `width: 100%` + `text-align: left` so the rule survives a row becoming a `<button>` again.
- Nothing predictive is shown. The at-risk list was removed with the `risk_*` tables; the dashboard reports what teachers have recorded.
