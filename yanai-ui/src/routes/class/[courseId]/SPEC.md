## Purpose
Class dashboard ("Foco" layout) for one class: a name headline + mono sub-line, a hero for
today's session whose only dark element is its action button, a quiet hairline-ruled nav list
into the criterios de evaluación and the class-wide "Añadir evidencia" action, and two
horizontal rails of upcoming and past sessions. Every session card is an entry into that
session's lesson screen, which is the app's only roster surface.

## Contents
- `+page.svelte` — loads `getClassDashboard` + `getGradingComponents` + `getClassCriteria` (`Promise.all`; the latter two feed the evidence dialog only). Renders: `.clsname` headline + `.clscount` mono sub-line; a `.hero` for `next_session` (only when non-null) with a clock-derived phase label, the start time at 40px, a topic line and the dark "Ver alumnos" button into `lesson/{session_id}`; a `.quiet` nav with a link row into `criteria/` (trailing `chevron-right`) and an "Añadir evidencia" `<button>` (trailing `plus`) opening `AddEvidenceDialog` with `scope="class"`; and two `.hscroll` rails of `.lcard`s for `upcoming` and `past`, each a date block beside the topic — upcoming showing the time range, past showing the attendance / pendientes / comentarios chips.

## Inputs / Outputs
Route param `courseId` (class UUID); consumes `lib/api/endpoints/classes.ts` and `criteria.ts`, and reads `usesInternalGrading` from `lib/stores.ts`. One mutation: `createAssessment` without `student_id`, i.e. evidence for the whole class.

## Conventions & Constraints
- Term selection defaults to the current term server-side (`term_id` query optional).
- **The screen is built from the approved "Foco" mockup and must stay identical to it.** Its measurements are deliberate and are not the app-wide defaults, so this route overrides three global rules locally: `.body` padding (`22px 18px 30px`), `.eyebrow` (11px/600, `0.08em`, uppercased by CSS rather than in the markup) and `.chip` (`3px 9px`, `white-space: nowrap`). Changing those to "match the rest of the app" would break the design.
- **The hero block is plain; the button is the only dark element on the screen.** That is what makes it the one obvious action — an inverted hero (dark card, light button) reads as a banner and loses it. The button label is "Ver alumnos", not "Iniciar clase": it goes to the lesson screen, which is where the roster is, and nothing on this screen starts a session.
- **The rails bleed past the body gutter** (`margin: 0 -18px 30px` against `padding: 0 18px 8px`) so a card can sit half-cut at the phone edge. That cut is the only thing telling you the row scrolls, so the gutter number is duplicated here rather than inherited.
- **Nothing aggregate is rendered.** `ClassDashboardDto` still carries `distribution`, `stats`, `grades_pending`, `attendance_unmarked`, but the screen renders none of them — it is a launcher, not a report. (This corrects a stale claim: the spec previously described a rendered "Distribución de logros" bar, which had already been cut from the file.)
- **The hero phase label is clock-derived, not `status`-derived.** `next_session` exists only because the server query filters `status` to `scheduled`/`in_progress`; the "Hoy · …" label is then computed from `scheduled_start_at`/`scheduled_end_at` (full RFC3339 instants) against a `now` refreshed every 60 s while the page is open: `now < start` → Sin iniciar, `start ≤ now ≤ end` → En curso, `now > end` → Finalizada. `cancelled`/`rescheduled` sessions never reach the hero, so the three phases are total. The phase is computed in-template (`{@const}` under the `{#if}`) so it re-reads `now` on each tick, and the labels are written in sentence case because `.hero-lbl` uppercases them in CSS.
- **This is where class-wide work is set up, and only class-wide work.** The dashboard is the screen that speaks for the class, so filing a column every student will be graded on belongs here; anything scoped to one student belongs on that student's screen. The dialog states its scope in a caption rather than offering a picker. The screen deliberately does not refetch after filing evidence — a new piece has no levels and no marks yet, so nothing it shows would change.
- The second nav row is a `<button>` (opens the dialog), not an `<a>`; `.quiet-row` sets explicit `width: 100%` + `text-align: left` because a `<button>` does not get those from the row layout for free.
- Nothing predictive is shown. The at-risk list was removed with the `risk_*` tables; the dashboard reports what teachers have recorded.
