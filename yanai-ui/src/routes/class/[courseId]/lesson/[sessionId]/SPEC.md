## Purpose
The lesson screen — the app's core loop and its **primary destination**: find one student by name, hold the bubble, leave a voice note. Every row on Home opens this screen directly. There is no roster list and no attendance.

## Contents
- `+page.svelte` — binds to `lib/lesson.ts` (`loadSession`, `addNote`, `removeNote`) and to the `students`/`entries`/`notes` stores. Renders a fixed stage: a header (the `.metacard` context card — área + fecha over a hairline, then the lesson's topic / the search-and-name line / a mono sub-line / the results panel / the "Ir a {área}" button, when shown — see `cameFromArea` below), one `RecordBubble` anchored below it, a pinned hint and countdown, and the selected student's notes of the day as `VoiceNotePlayer` rows (playback + delete only — see below).

## Inputs / Outputs
Route params `courseId`, `sessionId`; every mutation goes through `lib/lesson.ts` (optimistic autosave, revert on API error). One read: `getSession` via `loadSession`.

## Conventions & Constraints
- No submit button by design — every interaction saves immediately.
- **The body is a fixed stage.** Everything is absolutely positioned off the stage's edges or off `--bubble-anchor`, and the route sets its own `100dvh` flex column instead of using the global `.body` gutter. Nothing reflows between the three states: the bubble never moves and never changes size — only its colour and its drift speed change.
- **The stage's anchors are four variables on `.stage`, and they vary by viewport only — never by state.** `--bubble-anchor` places the orb's centre; `--bubble-scale` shrinks it on a short screen; `--hint-offset`, `--count-offset` and `--notes-offset` hang the hint, the countdown and the notes panel off that same anchor, so the composition moves as one piece. Two rules behind them: (1) they must never differ between the searching / armed / recording states — the approved artboard once drew the hint 4px higher while recording, and that 4px is exactly the reflow this design forbids; (2) the anchor is a **fixed px distance from the top, not a percentage**. The header above it is a constant 324px tall, so px anchoring keeps the same gap under it on every screen and hands the slack on a tall screen to the notes panel, which is the only part that can use it; a percentage put the orb behind the header on short screens and left a hole on tall ones.
- **The context card is the session's identity, and it never changes height.** Área (`class_name`), fecha (weekday + day + month, built from two `toLocaleDateString` calls so the separator is not left to an ICU version) and the lesson's topic — with the class dashboard's own `Sin tema asignado` for a session that has none, deliberately the same string, since it is the same absence. All three are constant for the whole session, which is what lets the header's height be the constant the anchor rule above depends on. The sub-line still reserves its height (`min-height`) when empty so the results panel below never jumps.
- **"Ir a {área}" is navigation on the stage, and where it appears it is the header's last element.** A full-width gradient button below the sub-line, leading to `/class/{courseId}`. Being last is load-bearing: hiding it moves nothing above it, which is why the old `.metarow`'s `min-height: 24px` is gone rather than forgotten — that rule existed because the pill used to sit *inside* the header, where its disappearance would have shifted the name line. It carries the bubble's own `--aurora-*` palette rather than a neutral pill: where it shows, it is the one thing on the screen that is not the recording, and it has to be findable without hunting. Gated on three conditions: `stage !== 'recording'` (`.head.receded` only drops the header to `opacity: .45` and leaves it tappable, and navigating away mid-hold would lose the note), `!panelOpen` (while the picker is open the list is the task and the button would otherwise trail 46vh of names), and — since 2026-09-08 — **`!cameFromArea`**.
- **`cameFromArea` (`page.url.searchParams.get('from') === 'area'`) hides the button entirely, and that is deliberate, not a bug.** área's hero and both rails mark their links `?from=area`; when the param is present, this bubble already has that exact área page sitting one entry behind it in browser history, and the back arrow (`useHistory`, below) already lands there for free. Without this, área ⇄ burbuja was a loop with no way to shrink: both directions are ordinary forward `<a href>`s, so a lap of área → session → "Ir a área" → área → another session → … pushed one history entry per hop, forever, rather than reusing the entry already there. A bubble reached from **Home** carries no `from` param — Home never links to área at all, so for that entry point "Ir a {área}" is the *only* way there, and it stays. `cameFromArea` is read once from `page.url`, which does not change while the bubble is open (student selection is local state, not a navigation), so this never flips mid-session.
- **The header sits above the pinned hint (`z-index: 4` against the hint's 3).** The results panel is part of the header, and at the same z-index the hint printed straight through the list of names the panel is busy answering.
- **The notes panel is bounded by the anchor, not by its own content.** It is pinned `top: calc(var(--bubble-anchor) + var(--notes-offset))` to `bottom: 0` and the list scrolls inside it, so a student with six notes grows a scrollbar instead of growing up over the bubble.
- **On a short viewport (`max-height: 800px`) the stage scrolls instead of hiding the notes.** Until 2026-09-10 the whole `.notes` panel was `display: none` below 800px — which is almost every phone once the browser's address bar shows, so the teacher recorded a note and never saw the list. Now, only when there are notes to reach (`.screen.withnotes`, bound to the `showNotes` derived = a student is selected, not recording, and `selectedNotes.length > 0`), `.stage` becomes an `overflow-y: auto` / `overflow-x: hidden` scrollbox and `.notes` drops its `bottom: 0` pin for `position: static` with `margin-top: calc(var(--bubble-anchor) + var(--notes-offset))`, so the list flows below the fixed composition and the list itself stops scrolling internally (`.notelist { overflow-y: visible }`). `.stage` is `flex: 1` in a 100dvh column, so its scrollbox is exactly one viewport tall and the composition still fills the first screenful; everything on the stage is absolutely positioned, so header/orb/hint scroll away with the content while `TopBar` stays put. During recording and when the selected student has no notes, `showNotes` is false and the stage is the untouched fixed stage. No auto-scroll — the list sits one swipe below the orb.
- **The back arrow uses `useHistory`.** This screen is reached from Home (every rail and week row) and from the área's hero and rails, so the `back="/class/{courseId}"` href is only ever a cold-load fallback. Independent of `cameFromArea` above — that only gates the forward button; the back arrow behaves the same regardless of where the bubble was opened from.
- **One 360×360 bubble stage** (`viewBox 0 0 360 360`, `cx=cy=180`, orb `r=116`, gauge ring `r=132`) in all three states, so "never changes size" is structural rather than coincidental.
- **The roster is loaded but never listed.** `lesson.ts`'s `addNote` early-returns unless `entries` already holds `entryKey(sessionId, studentId)`, so `loadSession` must keep populating `students`/`entries`/`notes` even though nothing renders a list. Search filters `$students` client-side; `getSession`'s `q` parameter exists server-side and stays unused, because a roster already in the store answers between keystrokes and a round-trip would not.
- **The picker lists the whole roster when the query is empty.** With no roster anywhere else, this panel is the only route to a student, and requiring a teacher to type before any name appears would make a 30-student class unbrowsable.
- **Results rows commit on RELEASE, never on `pointerdown`.** A row holds the student from `pointerdown` (pointer captured, `TAP_SLOP = 10px` recorded) and calls `pick()` on `pointerup` only if the finger stayed inside that slop; movement past it, or a `pointercancel`, abandons the press. This is not a preference — committing on `pointerdown` made the panel **unusable by touch**: the first contact of a swipe selected a name and unmounted the list, so on a phone only the names already on screen were reachable. On iOS the old `preventDefault()` on `pointerdown` compounded it, since WebKit derives pointer events from touch events and preventing that default also suppresses the container's pan. `pointercancel` must abort rather than commit (the opposite of `ScoreRuler`, whose cancel commits): a cancel is the browser saying it took the gesture to scroll.
- **What the old `preventDefault()` protected is still protected.** It existed so a blurring search input — and the layout shift of the software keyboard closing — could not move the row out from under the finger before the tap resolved. Three things replace it: the student is captured at `pointerdown` rather than hit-tested at release, the pointer is captured to that row, and `pointerup` fires *before* the focus change, with `pick()` closing the panel and blurring the field itself. The commit then calls `preventDefault()` on the **`pointerup`**, which suppresses the compatibility click that would otherwise land on whatever the closing panel uncovers — the "Ir a {área}" button sits right there.
- **The row's `onclick` is the keyboard path, and only that.** It commits solely when `event.detail === 0` (keyboard- and AT-generated clicks); every pointer-driven click is already prevented above. Before this the row was a `<button role="option">` with no click handler at all, so Enter did nothing.
- **`.rrow` carries `touch-action: pan-y`** so the browser may start scrolling the panel on the first move instead of waiting on script, plus `user-select`/`-webkit-touch-callout: none` so a slow drag over a name does not raise iOS's text-selection menu over the list. `.results` carries `overscroll-behavior: contain`. Re-verified 2026-09-08: no `preventDefault()` on `pointerdown`/`pointermove`, only on the confirmed-tap branch of `pointerup`, so nothing here blocks native scroll on either iOS or Android.
- **A voice note saves in full automatically — recording it is the only action.** `VoiceNotePlayer` has no "Guardar" control; `lib/lesson.ts`'s `addNote` creates the note (`status: 'draft'`) and immediately chains the call that marks it `'saved'`, with one silent retry if that second call fails. The row's only control besides playback is delete, via `ConfirmDialog` (ported to `document.body` — see `lib/components/SPEC.md` — so it always renders as a true page-level overlay regardless of this screen's own `.head`/`.notes` z-index layering below).
- **The name line is the search field.** The chosen name is painted over an empty input as an `aria-hidden` overlay rather than set as its value, which keeps "typing replaces the name" true without a did-they-edit-it state machine.
- **The "x" button (`clearAll`) means two different things, chosen by whether a student is already
  picked.** With a selection, it starts over: clears the selection and re-opens the picker, because with
  no roster on screen the panel is the only way to reach a student. Without one, the panel is already
  open, and the button actually closes it (`searching = false`) instead of re-opening what was already
  open — closing loses nothing, since the field's own `onfocus` re-opens the panel on the next tap. Its
  `aria-label` follows the same split ("Borrar y elegir otro alumno" / "Cerrar lista de alumnos").
- **Recording is gated on a student being chosen and on nothing else.** It is never gated on attendance — there is no attendance here or anywhere else in the app.
- Nothing about achievement is shown. There is no `PROMEDIO DE SECCIÓN` card and no per-student level: a nivel de logro is a judgement over a period's evidence (RVM 094-2020, 5.1.1.3 p.2-3) and does not belong beside a name being recorded against. It is read and written on the student's grades screen, where the evidence is.
- No scroll position is persisted, because there is no scroll.
- Nothing here is risk-driven. The predictive subsystem (`risk.detect` and everything behind it) was removed whole in `migrations/00003`.
